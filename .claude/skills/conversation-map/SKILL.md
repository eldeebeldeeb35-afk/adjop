# خريطة المحادثة

الفكرة: المحادثة الطويلة غالية في القراية. بدل ما ترجع لكل رسالة، احتفظ **بخريطة واحدة قصيرة** وامشي عليها.

## ١. الخريطة الحية (بتتحدث أثناء الشغل)
ملف واحد لكل مشروع: `.claude/map.md` في جذر الريبو (أو في فولدر الشغل). شكله:

```markdown
# خريطة: <اسم الشغل>
**الهدف**: جملة واحدة.
**آخر تحديث**: <تاريخ> — <رقم الطلب>

## القرارات (ثابتة، متتناقشش تاني)
- ...

## اللي خلص
- [x] ... (`ملف/مسار`)

## اللي فاضل (بالترتيب)
- [ ] ...

## مستني حمدي في
- ...

## ملفات مهمة
| الملف | ليه |
|---|---|

## الخطوة الجاية بالظبط
سطر واحد.
```

**امتى تحدّثها**: بعد كل خطوة كبيرة خلصت، بعد أي قرار من حمدي، وقبل `/compact` أو قفل الجلسة. التحديث = تعديل سطور، مش إعادة كتابة.
**امتى تقراها**: أول ما الجلسة تبدأ أو ترجع، وبعد أي compaction، وقبل ما تبعت شغل لـ subagent (ابعتله الخريطة بدل المحادثة).

## ٢. خريطة من محادثة قديمة (أوتوماتيك)
```bash
python scripts/session_map.py --list                 # الجلسات المتاحة
python scripts/session_map.py --out /tmp/map.md      # أحدث جلسة
python scripts/session_map.py <session.jsonl> --out map.md
```
بيطلع لكل طلب: الطلب، الأدوات، الملفات اللي اتغيرت، الأوامر، وأول الرد، وفي الآخر مخطط Mermaid.
جربته على جلسة 2.2 ميجا طلع 2 كيلو. اقرا الناتج، وبعدين اكتب منه الخريطة الحية (الجزء ١) بالقرارات واللي فاضل.

## ٣. خريطة بصرية لحمدي
لو حمدي عايز يشوف الخريطة: اعملها Mermaid `flowchart` (الطلبات ← اللي اتعمل ← اللي فاضل) أو صفحة Artifact صغيرة. للاستخدام الداخلي بتاعك، الماركداون كفاية وأرخص.

## قواعد
- الخريطة قصيرة: لو عدّت 80 سطر، اختصر «اللي خلص» لسطر لكل مرحلة.
- اكتب **قرارات** حمدي بكلامه، عشان متتناقشش تاني.
- متكتبش أسرار أو باسووردات في الخريطة.
- لو الخريطة والكود مختلفين، الكود هو الصح؛ صلّح الخريطة.
